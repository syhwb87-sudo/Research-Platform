# PRIDE 연구활동 종합관리 Dashboard 설계서

> 연구관리 시스템(PRIDE) 첫 화면 — "연구과제 관리"가 아닌 **"연구활동 포트폴리오 관리"** 를 위한
> Enterprise Grade Dashboard 설계 문서.
>
> 대상 사용자: 연구원 / 팀장(그룹리더) / 연구소장 / 경영층(기술연구원장·CTO)
> Demo 데이터: a1~a6 CSV 6종 (실운영 시 PRIDE Backend DB 연동)

---

## 0. Brainstorming — Dashboard 아이디어 34선

관점별로 아이디어를 발산한 뒤, 이후 장에서 IA·위젯으로 수렴시킨다.

### 경영자(CTO/기술연구원장) 관점 — "R&D 투자가 사업성과로 돌아오고 있는가"

| # | 아이디어 | 핵심 질문 |
|---|---|---|
| 1 | **R&D Portfolio Balance Map** — 6개 활동군을 투입 MW·예산 기준 트리맵으로 표시 | 자원이 전략에 맞게 배분되는가 |
| 2 | **R&D ROI Waterfall** — 총연구비 → 기대이익 → 실현이익으로 이어지는 폭포수 차트 | 돈이 성과로 전환되는가 |
| 3 | **Promise vs Delivery Gauge** — 완료과제의 기대이익 대비 실현이익 Achievement % | 약속한 성과가 실현됐는가 |
| 4 | **전략-현업 Balance Beam** — 전략 프로젝트 vs 현업지원 MW 비율을 저울 형태로 시각화 | 미래와 현재의 균형 |
| 5 | **Innovation Runway** — 탐색·혁신(N과제) 비중 추이 + 목표선(예: 총 MW의 15%) | 미래 씨앗을 뿌리고 있는가 |
| 6 | **누적 실현성과 Cumulative Impact Curve** — 연도별 실현이익 누적 곡선 vs 연구비 누적 | 손익분기 시점 파악 |
| 7 | **Top 10 Value Creator 과제 리더보드** — 투자효율(ROI) 상위 과제 | 성공 사례의 공통점 |
| 8 | **미활용 자산 Alert** — 완료 후 미활용 과제의 매몰 연구비 총액 | 어디서 새는가 |
| 9 | **탄소중립/ESG 기여 카드** — CO₂ 저감량, 환경비용절감 합계 | 지속가능 경영 기여 |
| 10 | **One-Page Executive Brief** — 위 1~9를 A4 한 장 밀도로 압축한 임원 전용 화면 | 5분 안에 전체 파악 |

## 1. Dashboard 전체 정보구조 (IA)

### 1.1 설계 원칙

1. **Portfolio First** — 첫 화면은 개별 과제가 아니라 6개 활동군의 분포·균형·성과를 보여준다.
2. **Role-Adaptive** — 동일 IA에서 역할(연구원/팀장/소장/경영층)에 따라 기본 필터와 첫 화면 위젯 구성이 달라진다.
3. **3-Click Rule** — 종합현황 → 활동군 상세 → 개별 과제/인물, 어떤 정보든 3클릭 내 도달.
4. **Drill Everywhere** — 모든 집계 숫자는 클릭 시 근거 목록(과제/인원/건)으로 전개된다.
5. **Time Machine** — 모든 화면에 기간 선택기(연도/분기/월)와 전년 동기 비교가 기본 탑재된다.

### 1.3 계층 구조와 내비게이션

- **수직 드릴다운**: 전사 → 연구소 → 연구그룹 → 개인 / 활동군 → 과제 → 월별 상세.
  모든 페이지 상단에 breadcrumb(`전사 ▸ 솔루션연구소 ▸ 강재솔루션연구그룹`)을 유지한다.
- **수평 전환**: 같은 계층에서 렌즈 전환 탭 — `MW 기준 | 예산 기준 | 건수 기준`.
- **글로벌 필터 바** (모든 페이지 공통, 화면 최상단 고정):
  `기간` `연구소` `연구그룹` `활동군` `기술분류` `진행상태`
- **역할 프리셋**: 로그인 역할에 따라 Home 위젯 세트가 다르게 로드된다.
  - 경영층 → Executive View가 Home
  - 연구소장 → Home + 소속 연구소 필터 프리셋
  - 팀장 → Home + 그룹 필터 프리셋, MW 위젯 확대
  - 연구원 → My Dashboard가 Home, 종합현황은 탭으로 접근

## 5. Man Week Dashboard

**핵심 질문**: "연구원들의 시간이 어디에 투입되고 있으며, 그것이 의도된 배분인가?"

### 5.1 화면 구성 (4개 탭)

```
┌─────────────────────────────────────────────────────────────────┐
│ MW 분석   [① 조직별] [② 활동유형별] [③ 개인] [④ 시뮬레이션]         │
├─────────────────────────────────────────────────────────────────┤
│ KPI: 총 투입 MW │ 활동인원 │ 인당 평균 MW │ 데이터 입력률 96% ⚠     │
└─────────────────────────────────────────────────────────────────┘
```

**① 조직별 (연구소 → 그룹 → 개인 3단 드릴)**

- **Heatmap (조직×월)**: 셀 색 = MW 강도. 과부하 셀(적색)·유휴 셀(회색) 즉시 식별.
- **조직 Stacked Bar**: 조직별 총 MW를 활동군 색으로 적층 — "공정DX연구소는 현업 비중이 크고, 미래철강연구소는 탐색 비중이 크다"가 한눈에.
- 드릴: 연구소 막대 클릭 → 그룹별 분해 → 그룹 클릭 → 개인별 테이블.

**② 활동유형별**

- **100% Stacked Area (월별)**: 6개 활동군 구성비의 시계열 변화 — 제도 개편 효과 추적의 핵심 차트.
- **Sankey Diagram**: 조직(좌) → 활동군(우) MW 흐름. "누가 어디에 시간을 대는가"를 흐름으로.
- 전년 동기 대비 활동군별 증감 워터폴.

**③ 개인 Utilization**

- 개인별 행: `이름 │ 그룹 │ 활동군 미니 스택바 │ 총 MW │ 부하율 게이지 │ 참여과제수`
- 부하율 = 투입 MW ÷ 가용 MW(월 4.3 기준). 130% 초과 적색 / 70% 미만 회색 표시.
- 멀티태스킹 경보: 동시 4과제 이상 참여자 플래그.
- 개인 클릭 → My Dashboard 뷰(월별 잔디밭, 과제 목록, 활동 이력).

**④ 투입 시뮬레이션 (팀장 도구)**

- 신규 과제 예상 MW를 입력하면 그룹 잔여 여력과 개인별 배정 가능량을 계산해 표시.
- "이 과제를 받으면 누가 과부하가 되는가"를 사전에 답한다.

### 5.2 데이터 처리 규칙 (a2 기반)

- MW 활동군 매핑: a2.과제코드에 `W` 포함 → 현업, `N` 포함 → 탐색, 그 외 → 전략. (a5·a6 활동은 MW 데이터가 없으므로 MW 렌즈에서는 제외하고 건수 렌즈로만 표시 — 실운영 시 근태/활동입력 연동으로 확장)
- 월별 컬럼(1월~12월)을 unpivot하여 `fact_manweek(과제, 연구원, 년월, MW)`로 적재 (→ 8장).
- **입력률 KPI**를 항상 노출: 미입력 데이터 위에 세운 분석은 신뢰를 잃는다.

            (기대성과     활용평가   활용평가   활용평가   활용평가   활용평가    (누적성과
             확정:        └────────┴────────┴────────┴────────┴───────┘     확정)
             년간기대이익,        매 차수 기록 항목:
             기술지속년수,        · 활용상태: 활용중 / 부분활용 / 미활용
             총기대이익)          · 실현성과: 매출/원가절감/생산성/품질/안전/환경 (6개 축)
                                · 실현금액, 산출근거, 검증자(활용부서)
                                · 미활용 시: 사유코드 + 조치계획
```

- **Achievement % (과제)** = 누적 실현이익 ÷ (년간기대이익 × 경과년수, 기술지속년수 상한)
- **Achievement % (전사)** = Σ실현 ÷ Σ기대 (완료연도 코호트별로도 산출)
- **검증체계**: 실현성과는 연구부서가 아닌 **활용부서(활용책임자)가 입력·승인**하고,
  재무효과는 성과검증 주관부서(예: 생산기술전략실)가 확정하는 3자 검증 워크플로를 전제로 설계.
  대시보드에는 `검증완료/검증대기/자체추정` 상태 배지를 항상 병기한다.

## 8. Demo DB 설계 (CSV 기반 Star Schema)

### 8.1 설계 방침

- CSV 6종을 **ETL 스크립트(로드 시 1회)** 로 정규화하여 Fact/Dimension으로 분리.
- 활동군 분류는 ETL 단계에서 규칙으로 부여(`dim_activity_type` FK) → 화면 로직에서 문자열 파싱 제거.
- 금액은 원 단위 정수, MW는 소수 1자리, 날짜는 ISO 8601로 클렌징(현재 CSV는 공백·콤마 포함 문자열).

### 8.2 ERD (Star Schema)

```

                        │ dim_date           │
                        │ date_key (PK)      │
                        │ 연도/분기/월          │
                        └─────────┬──────────┘
                                  │
┌──────────────────┐   ┌──────────┴──────────┐   ┌───────────────────┐
│ dim_activity_type│   │      FACT 군        │   │ dim_org           │

│ 1 전략프로젝트      │   │ fact_manweek        │   │ 연구소/그룹/섹션 계층 │

### 8.3 테이블 명세

**Dimension**

| 테이블 | 원천 | 주요 컬럼 | 비고 |
|---|---|---|---|
| `dim_project` | a3 (a1·a2 과제코드 통합) | project_key, 과제코드, 과제명, 과제유형, 연구성격, activity_key, 착수일, 완료일, 총단계, 연구부서→org_key, 연구책임자→researcher_key, 활용부서→org_key, 보안등급 | **activity_key 규칙**: 과제코드 LIKE '%W%'→3, '%N%'→4, 그 외→1 |
| `dim_org` | a1~a6 부서명 파싱 | org_key, org_name, 연구소, 그룹, 섹션, level | `솔루션연구소 강재솔루션연구그룹` → 계층 분해. 파견/휴직은 별도 플래그 |
| `dim_researcher` | a2 성명+a5 직번 | researcher_key, 성명, 직번, 직능등급, 현소속 org_key | 동명이인은 직번 우선 매칭 |
| `dim_tech` | a1/a3/a4/a5 기술분류 | tech_key, 대분류(제품/공정/이용/엔지니어링…), 중분류, 원문 | `(제품)선재제품-선도제품개발기술` 패턴 파싱 |
| `dim_date` | 생성 | date_key(YYYYMMDD), 연/분기/월/주차 | 표준 달력 |
| `dim_activity_type` | 코드표 | activity_key(1~6), 활동군명, 색상토큰, 목표비중 | 목표비중은 관리자 설정 |

**Fact**

| 테이블 | 원천 | Grain (1행) | 측정값 | 주요 FK |
|---|---|---|---|---|
| `fact_manweek` | a2 unpivot | 과제 × 연구원 × 년월 | mw | project, researcher, org, date, activity |
| `fact_project_status` | a3 | 과제 × 스냅샷월 | 연구비, 확정/집행예산, 참여인력수, 참여MW, 기대이익, 실현이익, 진행상태 | project, org, tech, date |
| `fact_completion` | a1 | 완료과제 × 1 | 총연구비, 집행실적, 년간기대이익, 기술지속년수, 연구기여도, 총기대이익, 투자효율, 완료평가점수 + 효과유형 14컬럼 unpivot → `fact_expected_effect`(과제×효과유형×금액) | project, org, tech, date(완료평가일) |
| `fact_utilization` | a1+a3(활용평가차수/상태) ※Demo에선 시뮬레이션 생성 | 완료과제 × 평가차수(1~5) | 활용상태(활용중/부분/미활용), 실현액(매출/원가/생산성/품질/안전/환경 6컬럼), 검증상태, 미활용사유 | project, org(활용부서), date(평가일) |
| `fact_support` | a4 | 지원요청 × 1 | 리드타임일수, 지연여부, 건수=1 | org(요청/대응), researcher(담당), tech, date(요청/완료) |
| `fact_knowledge` | a5 | 활동 × 1 | 건수=1, 활동구분, 참가여부 | researcher, org, tech, date(기안/참가) |
| `fact_promotion` | a6 | 홍보건 × 1 | 건수=1, 진행상태 | org(연구그룹), researcher(담당), date(홍보일) |

### 8.4 관계도 설명

1. 모든 Fact는 `dim_project`(해당 시) + `dim_org` + `dim_date` + `dim_activity_type`을 공유한다
   → **활동군×조직×기간**이라는 동일한 축으로 6개 활동군을 한 화면에서 합산·비교 가능. 이것이 "통합 포트폴리오" 요건의 데이터적 토대다.
2. `fact_manweek` ↔ `fact_project_status`는 project_key로 연결되어 "MW를 쓴 만큼 예산·성과가 따라오는가"를 조인 없이 dim 경유로 분석.
3. `fact_completion`(기대) ↔ `fact_utilization`(실현)이 project_key로 짝을 이뤄 Achievement % 산출.
4. **Demo 한계 명시**: a1·a3에는 연차별 활용평가 실적값이 없으므로, Demo에서는 `fact_utilization`을
   기대이익×난수 활용률로 생성한 **시뮬레이션 데이터**로 채우고 화면에 'DEMO' 워터마크를 표시한다.
   실운영 전환 시 이 테이블만 PRIDE 활용평가 모듈로 교체하면 된다(인터페이스 불변).

### 9.4 Charts 규칙

- 라이브러리: ECharts 또는 Recharts 단일화 (혼용 금지).
- 활동군 비교 = **막대/트리맵**, 시간 추이 = **라인/영역**, 구성비 = **100% 스택** (파이는 5조각 이하일 때만).
- 흐름·전환 = **Sankey** (Value Flow, 활용상태 Flow 전용).
- 모든 차트: 툴팁에 값+구성비+전년 동기 병기, 축 단위 명시(억원/MW/건), 3D·이중 Y축·장식성 그라디언트 금지.
- 숫자 포맷: 천 단위 콤마, 금액은 억원 환산(1억 미만은 백만원), MW 소수 1자리.

### 9.5 UX Principles

1. **Overview → Zoom → Detail** (Shneiderman): 첫 화면은 집계만, 상세는 드릴로.
2. **모든 숫자는 행동으로 연결**: KPI 클릭 → 근거 목록 → 담당자/과제. 막다른 숫자를 만들지 않는다.
3. **비교 없는 숫자 금지**: 목표·전년·타 조직 중 최소 1개의 비교 기준을 항상 병기.
4. **신뢰 표시**: 데이터 기준일, 입력률, 검증상태(6.1)를 화면에 상시 노출.
5. **성능**: 첫 화면 2초 내 렌더(집계 사전계산), 드릴다운 1초 내.
6. **접근성**: 색약 대응(활동군색은 명도차 확보 + 패턴 보조), 키보드 내비게이션, 표 대체 뷰 제공.

## 10. 최종 추천안

### 추천: "Portfolio Command Center" 구성 (2장 첫 화면 + 6장 장기성과 + 7장 Executive의 3면 체제)

**Phase 1 (Demo, CSV 기반)**
1. Home 종합현황 (2장 레이아웃 그대로)
2. 장기성과 관리 대시보드 (6장 — 활용평가 데이터는 시뮬레이션, 'DEMO' 워터마크)
3. Executive One-Page (7장)
4. MW 분석 ①②탭 (5장)

**Phase 2 (PRIDE 연동 후)**: 활동군별 상세 6종, My Dashboard, 시뮬레이터, 알림 연동.

### Why? — 이 구성이 경영층을 설득하는 이유

1. **제도 개편의 스토리를 화면 구조가 그대로 증명한다.**
   "과제관리 → 활동 포트폴리오 관리"라는 개편 취지가 첫 화면 트리맵과 균형 진단 위젯에서
   즉시 시각적으로 확인된다. 대시보드 자체가 제도 개편의 설명 자료가 된다.

2. **경영층의 최종 질문은 언제나 "그래서 돈이 됐는가"이다.**
   기존 R&D 대시보드가 투입·진행만 보여주다 끝나는 것과 달리, 이 설계는
   완료평가(기대) → 1~5년차 활용평가(실현) → Achievement %로 이어지는
   **성과 실현의 전체 사슬**을 중심에 둔다. a1 데이터의 년간기대이익·투자효율은
   이미 이 스토리를 시작할 수 있는 실데이터다.

3. **긴장 관계를 숨기지 않고 관리 대상으로 만든다.**
   전략:현업 균형, 탐색 비중 미달, 미활용 매몰비용 같은 '불편한 숫자'를
   목표 대비 상태로 상시 노출한다. 경영층은 잘 되는 것보다 "무엇이 위험한지 아는 시스템"을 신뢰한다.

4. **역할별로 같은 데이터, 다른 첫 화면.**
   임원은 One-Page, 소장·팀장은 종합현황+MW, 연구원은 My Dashboard —
   전 구성원이 매일 열어볼 이유가 있어야 데이터 입력이 살아 있고, 그래야 경영 보고 숫자가 신뢰를 얻는다.
   (연구원에게 대시보드는 감시가 아니라 **자기 활동의 인정 장치**로 설계됐다 — 아이디어 27~34.)

5. **Demo에서 실운영까지 다시 만들 것이 없다.**
   Star Schema(8장)는 CSV와 PRIDE DB 어느 쪽이든 같은 인터페이스로 적재된다.
   Demo에서 검증한 화면이 그대로 운영 화면이 되므로, 시연 성공이 곧 구축 착수 승인으로 이어진다.

> **한 문장 요약**: 이 대시보드는 "연구를 얼마나 했는가"가 아니라
> **"연구가 회사를 얼마나 바꿨는가"** 를 보여주는 화면이며,
> 그것이 6개 활동군 체계로 제도를 개편한 이유 그 자체다.
