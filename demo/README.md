# PRIDE Demo Dashboard

`docs/PRIDE_Dashboard_Design.md` 설계서의 **Phase 1** 구현체입니다.
CSV 6종(a1~a6) 기반의 정적 데모로, 백엔드 없이 브라우저만으로 동작합니다.

## 실행

```bash
cd demo
python3 -m http.server 8080
# 브라우저에서 http://localhost:8080 접속
```

(`index.html`을 파일로 직접 열어도 동작합니다 — 데이터가 `demo_data.js`로 내장되어 있습니다.)

## 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 대시보드 본체 — 홈 종합현황 / **My Dashboard(Researcher's Guild)** / 활동군 상세(6종) / MW 분석 / **성과 플랫폼(P-1 목업)** / Executive / 투입 시뮬레이터 7개 탭 |
| `demo_data.js` | ETL 산출물 (집계 데이터, 자동생성) |
| `etl.py` | CSV → 집계 데이터 변환 스크립트 (`python3 etl.py`로 재생성) |
| `data/a1~a6*.csv` | 원천 Demo DB (완료평가 / ManWeek / 연구과제 / 현업지원 / 학회활동 / 기술홍보) |
| `vendor/echarts.min.js` | ECharts 5.5.0 (오프라인 동작용 로컬 사본) |

## My Dashboard — Researcher's Guild 산정 모델

게이미피케이션 레이어는 **새 데이터를 만들지 않고** 기존 `D.me`(a1~a5 파생) 위에서
계산되는 파생 지표다. 규칙은 `index.html`의 `GUILD` 객체 한 곳에만 정의되며,
연구원이 규칙을 알 수 있어야 행동이 바뀌므로 아래에 공개한다.

### Research Activity Score (0~100)

6개 축의 **전사 백분위**를 가중 합산한다. 원값이 아닌 백분위를 쓰는 이유는
축마다 단위(MW·건·억)와 분포가 달라 직접 합산이 불가능하기 때문이다.

| 축 | 원천 | 가중치 |
|---|---|---|
| 전략 프로젝트 | 전략 과제 투입 MW | 25% |
| 지식자산 | 논문·발표·학회 건수 (a5) | 20% |
| 성과 실현 | 참여 완료과제의 실현이익 합 (억) | 20% |
| 과제 참여 | 참여 과제 건수 | 15% |
| 현업 대응 | 현업 과제 투입 MW | 10% |
| 탐색·혁신 | 탐색 과제 투입 MW | 10% |

**Grade는 절대 점수가 아니라 전사 상대 분포로 부여한다** —
S+ 상위 2% · S 7% · A+ 15% · A 30% · B 60% · C 나머지.
(점수가 백분위 가중합이라 희소 축이 많을수록 값이 압축되어, 절대 임계값을 쓰면
대다수가 최하 등급으로 몰려 동기부여를 해친다.)

### EXP · Level

| 항목 | 계수 |
|---|---|
| 투입 Man Week | × 10 / MW |
| 참여 과제 | × 300 / 건 |
| 지식자산 | × 500 / 건 |
| 활용중 성과 | × 800 / 건 |
| 부분활용 성과 | × 400 / 건 |
| 실현이익 | × 50 / 억 |

레벨 임계값 `EXP(L) = 250 × L^1.6` — 현재 데이터 기준 중앙값 Level 6, 분포 1~27.
Tier: Explorer(1+) · Contributor(4+) · Practitioner(7+) · Specialist(10+) ·
Principal Researcher(13+) · Research Master(16+).
Tier는 성장 단계 표시이며 **인사 직급이 아니다** (직급 데이터는 원천에 없다).

### 배지 · 퀘스트 · 순위

- **배지 8종** — 달성 여부는 실제 실적으로만 판정하고, 미획득 배지는 남은 조건을 수치로 표시한다.
- **Growth Quest 4종** — 완료 상태를 실데이터로 자동 판정한다(가짜 체크 없음). EXP 값은 위 계수표를 따른다.
- **순위** — 종합 점수 기준 전사/조직 내 순위. Ranking 카드의 스파크라인과 전월 대비 증감은
  **월별 투입 MW 순위**(a2 실 시계열)로 산출하며, 카드에 기준을 명시한다.
- **Growth Insight** — 규칙 기반 문장. "지식자산 1건 추가 시" 시뮬레이션은 실제 분포로
  백분위·점수·순위를 재계산한 결과이며 추정 문구가 아니다.

> 활동 이력이 적은 연구원에게는 강점 문구 대신 성장 시작점 문구를 노출한다 —
> 이 화면은 평가 도구가 아니라 성장 기록이기 때문이다.

## 화면 라우팅

탭·활동군 상태는 URL 해시로 동기화되어 딥링크·뒤로가기가 동작합니다 (페이지 이동 없음).

| URL | 화면 |
|---|---|
| `#page=home` | 홈 종합현황 (기본) |
| `#page=act&activity=strategy` | 활동군 상세 > 전략 프로젝트 |
| `#page=act&activity=long-term-performance` | 활동군 상세 > **장기 성과관리·확산** (장기성과 대시보드 인라인) |
| `#page=mw` / `#page=pp` / `#page=exec` / `#page=sim` / `#page=my` | 각 탭 |

`activity` 슬러그: `strategy` · `long-term-performance` · `field-support` ·
`exploration` · `knowledge-asset` · `org-capability`.
구 링크 `#page=lt`(장기성과 전용 탭)는 활동군 상세 > 장기 성과관리·확산으로 자동 승계됩니다.

## 데이터 규칙

- **활동군 분류**: 과제코드에 `W` 포함 → 현업·고객 문제해결, `N` 포함 → 탐색·혁신, 그 외 → 전략 프로젝트.
  Demo 한정으로 `L`코드(신사업 시험과제)도 탐색·혁신으로 간주 (a2에 N코드 MW가 없기 때문 — `etl.py` 주석 참조).
- **활용평가 시뮬레이션**: 연차별(1~5년차) 활용상태·실현이익은 CSV에 실적값이 없어
  시드 고정 난수(seed 20260831)로 생성합니다. 화면의 `DEMO` 배지가 이 데이터를 표시하며,
  실운영 전환 시 PRIDE 활용평가 모듈 데이터로 `fact_utilization`만 교체하면 됩니다.
- 기준일: 2026-08-31 (기준일 이후의 계획 MW는 추이 차트에서 제외).
- **성과 플랫폼 탭(P-1)**: `docs/PRIDE_Performance_Platform_Design.md`의 로드맵 P-1 구현.
  성과 등록 12건·Rule Bank 9종·승인 큐·Lineage는 a1 실과제 기반의 **시드 고정 목업**이며
  (ERP 미연동), P-2에서 A그룹 2개 유형부터 실 ERP 연동으로 대체됩니다.
- **성과 플랫폼 ③ 산출 근거 추적**(구 Data Lineage): 성과 등록 12건마다 `etl.py`가 시드 고정으로 생성한
  `lineage`(ERP 스냅샷 ID·동결 시각·레코드 식별자 샘플, Rule 변수 대입값과 재계산 결과, 승인 이력, 연차별 활용평가,
  건전성 점검)를 근거 레인(과제→유형→Key→스냅샷→Rule)과 금액 레인(총액→−역효과→×기여율→−직접비용→순성과→승인→누적)
  두 줄의 흐름 그래프로 보여 줍니다. 재계산은 실제 변수값을 산식에 대입해 등록 성과총액과 대조(허용 오차 0.5%)하며,
  역효과 노드와 건전성 패널은 ⑤ 점검의 브라우저 저장 상태를 실시간으로 반영합니다.
- **성과 플랫폼 ⑤ 역효과(Erosion) 점검**: 구 "유형·매핑"(연구효과 14종 ↔ 재무성과 매핑 매트릭스)을 대체.
  재무성과 코드 16종(`etl.py PERF_TYPES`, A 4·B 10·C 2)을 단일 기준으로 **공통 체크리스트 8개 + 코드 그룹별 추가
  체크리스트(A 6·B 7·C 3)** 를 합산 표시하고(번호 기준 중복 제거, 적용 코드 배지), 코드별 역효과 대표 카탈로그 16건을 제공합니다.
  판정·근거·금액 등 사용자 입력은 `localStorage`(`pride.erosion.v1`)에 성과등록 ID별로 저장되며 샘플 데이터와 분리됩니다.
  `ErosionContext`(대상 성과)·`ErosionRepo`(저장소) 두 객체만 교체하면 PRIDE/Supabase 연동이 가능하도록 분리했습니다.
  조정 검토 요약의 금액은 단위별로만 집계하며(혼합 단위 합산 금지) 최종 재무성과에서 자동 차감하지 않습니다.
