# PRIDE Demo Dashboard

`docs/PRIDE_Dashboard_Design.md` 설계서의 **Phase 1** 구현체입니다.
CSV 6종(a1~a6) 기반의 정적 데모로, 백엔드 없이 브라우저만으로 동작합니다.

## 실행

```bash
cd demo
python3 -m http.server 8080
# 브라우저에서 http://localhost:8080 접속
```

(`index.html`을 파일로 직접 열어도 동작합니다 — 데이터가 `demo_data.js`로 내장되어 있습니다.)

## 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 대시보드 본체 — 홈 종합현황 / **My Dashboard(Researcher's Guild)** / 활동군 상세(6종) / MW 분석 / **성과 플랫폼(P-1 목업 — ① 자동산출 워크벤치 · ② 산출 근거 추적 · ③ 성과 총액 · ④ 역효과 · ⑤ 기여율 · ⑥ 재무실 승인 · ⑦ 성과 원장 · ⑧ 장기 활용평가)** / Executive / 투입 시뮬레이터 7개 탭 |

## My Dashboard — Researcher's Guild 산정 모델

게이미피케이션 레이어는 **새 데이터를 만들지 않고** 기존 `D.me`(a1~a5 파생) 위에서
계산되는 파생 지표다. 규칙은 `index.html`의 `GUILD` 객체 한 곳에만 정의되며,
연구원이 규칙을 알 수 있어야 행동이 바뀌므로 아래에 공개한다.

### Research Activity Score (0~100)

6개 축의 **전사 백분위**를 가중 합산한다. 원값이 아닌 백분위를 쓰는 이유는
축마다 단위(MW·건·억)와 분포가 달라 직접 합산이 불가능하기 때문이다.

| 축 | 원천 | 가중치 |
|---|---|---|
| 전략 프로젝트 | 전략 과제 투입 MW | 25% |
| 지식자산 | 논문·발표·학회 건수 (a5) | 20% |
| 성과 실현 | 참여 완료과제의 실현이익 합 (억) | 20% |
| 과제 참여 | 참여 과제 건수 | 15% |
| 현업 대응 | 현업 과제 투입 MW | 10% |
| 탐색·혁신 | 탐색 과제 투입 MW | 10% |

**Grade는 절대 점수가 아니라 전사 상대 분포로 부여한다** —
S+ 상위 2% · S 7% · A+ 15% · A 30% · B 60% · C 나머지.
(점수가 백분위 가중합이라 희소 축이 많을수록 값이 압축되어, 절대 임계값을 쓰면
대다수가 최하 등급으로 몰려 동기부여를 해친다.)

### EXP · Level

| 항목 | 계수 |
|---|---|
| 투입 Man Week | × 10 / MW |
| 참여 과제 | × 300 / 건 |
| 지식자산 | × 500 / 건 |
| 활용중 성과 | × 800 / 건 |
| 부분활용 성과 | × 400 / 건 |
| 실현이익 | × 50 / 억 |

레벨 임계값 `EXP(L) = 250 × L^1.6` — 현재 데이터 기준 중앙값 Level 6, 분포 1~27.
Tier: Explorer(1+) · Contributor(4+) · Practitioner(7+) · Specialist(10+) ·
Principal Researcher(13+) · Research Master(16+).
Tier는 성장 단계 표시이며 **인사 직급이 아니다** (직급 데이터는 원천에 없다).

### 배지 · 퀘스트 · 순위

- **배지 8종** — 달성 여부는 실제 실적으로만 판정하고, 미획득 배지는 남은 조건을 수치로 표시한다.
- **Growth Quest 4종** — 완료 상태를 실데이터로 자동 판정한다(가짜 체크 없음). EXP 값은 위 계수표를 따른다.
- **순위** — 종합 점수 기준 전사/조직 내 순위. Ranking 카드의 스파크라인과 전월 대비 증감은
  **월별 투입 MW 순위**(a2 실 시계열)로 산출하며, 카드에 기준을 명시한다.
- **Growth Insight** — 규칙 기반 문장. "지식자산 1건 추가 시" 시뮬레이션은 실제 분포로
  백분위·점수·순위를 재계산한 결과이며 추정 문구가 아니다.

> 활동 이력이 적은 연구원에게는 강점 문구 대신 성장 시작점 문구를 노출한다 —
> 이 화면은 평가 도구가 아니라 성장 기록이기 때문이다.

## 화면 라우팅

탭·활동군 상태는 URL 해시로 동기화되어 딥링크·뒤로가기가 동작합니다 (페이지 이동 없음).

| URL | 화면 |
|---|---|
| `#page=home` | 홈 종합현황 (기본) |
| `#page=act&activity=strategy` | 활동군 상세 > 전략 프로젝트 |
| `#page=act&activity=long-term-performance` | 활동군 상세 > **장기 성과관리·확산** (장기성과 대시보드 인라인) |
| `#page=mw` / `#page=pp` / `#page=exec` / `#page=sim` / `#page=my` | 각 탭 |
| `#page=exec&view=lab` / `&view=inst` | Executive › 연구원장 대시보드 / 연구소장 대시보드 (기본은 CEO) |

`activity` 슬러그: `strategy` · `long-term-performance` · `field-support` ·
`exploration` · `knowledge-asset` · `org-capability`.
구 링크 `#page=lt`(장기성과 전용 탭)는 활동군 상세 > 장기 성과관리·확산으로 자동 승계됩니다.

## 데이터 규칙

- **활동군 분류**: 과제코드에 `W` 포함 → 현업·고객 문제해결, `N` 포함 → 탐색·혁신, 그 외 → 전략 프로젝트.
  Demo 한정으로 `L`코드(신사업 시험과제)도 탐색·혁신으로 간주 (a2에 N코드 MW가 없기 때문 — `etl.py` 주석 참조).
- **활용평가 시뮬레이션**: 연차별(1~5년차) 활용상태·실현이익은 CSV에 실적값이 없어
  시드 고정 난수(seed 20260831)로 생성합니다. 화면의 `DEMO` 배지가 이 데이터를 표시하며,
  실운영 전환 시 PRIDE 활용평가 모듈 데이터로 `fact_utilization`만 교체하면 됩니다.
- 기준일: 2026-08-31 (기준일 이후의 계획 MW는 추이 차트에서 제외).
- **성과 플랫폼 탭(P-1)**: `docs/PRIDE_Performance_Platform_Design.md`의 로드맵 P-1 구현.
  성과 등록 12건·산식 18종·승인 큐·산출 근거 추적은 a1 실과제 기반의 **시드 고정 목업**이며
  (ERP 미연동), P-2에서 A그룹 2개 유형부터 실 ERP 연동으로 대체됩니다.
- **Executive 탭(CEO Dashboard)**: 재무실 **확정** 순재무성과만 보여 줍니다(`PF.regs` 중 상태 확정). 금년·누적 확정
  순재무성과, R&D ROI(확정 순성과 ÷ 해당 과제 연구비 `costEok`), 전환율(확정 순성과 ÷ 완료평가 기대이익), 검증 커버리지
  (등록 순재무성과 중 승인·확정 비중), 월별 확정 추이, A/B/C 그룹 트리맵, Top 5 과제, 검증 파이프라인(건수), 자동 브리핑,
  인쇄/PDF. 검토·승인 단계의 미확정 금액은 표시하지 않으며, ① 워크벤치의 등록·삭제가 즉시 반영됩니다. 이전의 a1·활용평가
  시뮬레이션 기반 Executive 데이터(`executive`)는 `demo_data.js`에서 제거했습니다.
- **Executive 탭 › 연구원장 대시보드**(`#page=exec&view=lab`): 성과의 구조 관점. KPI 5종(활동군별 확정 순성과 구성,
  탐색→전략 후속화율(근사: 탐색 완료 후 동일 연구부서·기술분류의 전략 과제 착수), 기술분류별 전환율 중앙값, 미활용 매몰비용,
  성과 파이프라인 단계별 금액), 기술분류(a3 대분류) × 재무성과 유형 히트맵(a1 정량효과→유형 기본 매핑, 기대이익), 파이프라인
  깔때기(등록·산출은 총액, 승인·확정은 순액), 활동군별 실현이익 추이(완료연도 스택), 기술분류별 전환율 표(확정 순성과 병기),
  Watch List(미활용 매몰비용 상위 / 활용중→부분·미활용 전환), 전환율 40% 미만 코호트 경보. 확정·파이프라인은 재무실 기준,
  기술·활동군 지표는 a1·활용평가 시뮬레이션 기준이며 카드마다 기준을 표기합니다. 데이터는 `etl.py`의 `perf.cto`.
- **Executive 탭 › 연구소장 대시보드**(`#page=exec&view=inst`): 조직 실행 관점의 연구소 필터 뷰. 연구소 선택 후
  KPI 6종(소속 등록 건수, 승인율, 보완·반려율과 사유 Top3, 평균 처리기간, 소속 확정 순재무성과, 활용평가 이행률),
  그룹별 성과 현황 스택바(등록/대기/승인/확정), 보완·반려 사유 파레토, 처리 지연 목록(SLA 잔여 3일 이하·경과 10일 초과),
  다가오는 활용평가 일정(완료일 기준 연차 도래, 6개월 내, 담당자), 전환율·이행률 벤치마크(연구소 vs 전사), 그룹별 순성과.
  연구소·그룹은 a1 연구부서("연구소 그룹")에서 나누며, 등록 건에 `lab`·`grp`를 추가했습니다. 데이터는 `etl.py`의 `perf.lab`.
- **성과 플랫폼 ⑦ 성과 원장**: 재무실 확정 건의 전사 원장(설계서 11.5). KPI 5종(금년·누적 순재무성과, 효과 대비 역효과
  비율, 평균 연구기여율(가중), A/B/C 구성비), 전사 워터폴, 유형별 트리맵(타일 클릭 → 원장 필터), 월별 추이(전년 비교는
  2025 확정 데이터가 없어 P-2), 연구소 × 유형그룹 스택바, 유형별 효과 vs 역효과 양방향 막대, 원장 테이블(② 추적 링크).
  범위 토글로 승인(확정 전) 건을 포함할 수 있고 검토 중 금액은 집계하지 않습니다. 등록·기여율 변경 시 즉시 갱신됩니다.
- **성과 플랫폼 ⑧ 장기 활용평가**: 연차 추적(설계서 11.6). 완료과제 활용평가 시뮬레이션에서 연차별 활용상태·실현액을
  기록하고, **성과상태(증가/유지/감소/종료)** 를 전년 대비 실현액 변화(±5%, 실현 0·미활용은 종료)로 파생합니다. KPI 5종
  (추적대상, 장기 활용률, 전환율, 평가 이행률, 성과상태 악화 건수), 활용상태 Flow Sankey(완료→1~5년차), 활용 × 성과상태
  매트릭스(활용중인데 감소·종료 셀 하이라이트, 클릭 → 시트 필터), 완료연도별 전환율 코호트 곡선, 2026 연차 재산출·평가
  캘린더(완료 월 기준 도래 차수), 미활용·종료 사유 파레토, 과제별 연차 추적 시트(연차별 상태·실현액·성과상태, 필터·검색).
  데이터는 `etl.py`의 `perf.util`. 원천에 성과상태 차원이 없어 파생 기준을 화면에 표기했습니다.
- **성과 플랫폼 ① 자동산출 워크벤치**: 5단계(성과 등록 → ERP 매칭·스냅샷 → 자동 산출 → 보정·검증 → 검토 요청·누적)를
  실제 진행 흐름으로 구현했습니다. **신규 등록 시뮬레이션**은 `PF.candidates`(완료과제 중 미등록 40건)에서 과제를 고르고
  18종 유형 카드에서 산식을 선택한 뒤, 산식의 대상 식별 Key를 입력하면 ERP 매칭 목업(`mockMatch` — Key 입력값을 시드로 한
  결정적 난수, 연동 지점)이 건수·집계값·레코드 샘플을 만들고 스냅샷을 동결합니다. 검토 요청 시 등록 건이 생성되어(`pride.regs.v1`)
  ②~⑥이 시드 목업과 동일하게 다루며, 초안은 `pride.regdraft.v1`에 자동 저장됩니다. 완료평가 정량효과 유형(14종)은
  참고 표기로만 남고, 상단 할 일 목록은 보완 요청·역효과 미작성·기여율 상향 대기·건전성 주의를 모아 해당 단계로 보냅니다.
- **성과 플랫폼 ③ 성과 총액**(구 Rule Bank): 재무성과 코드 18종(B-6(2) 수율 개선(매출이익형) 포함) 각각의 세부 산식을
  `etl.py RULES`에 변수 구조(`expr` = 곱셈항의 합, `varsDef` 변수 정의·원천·잠금, `keys` 대상 식별 Key)로 정의하고
  `PF.keyDict`(Key 사전 56종)와 함께 내보냅니다. 화면은 산식 카탈로그(그룹·패턴·검색 필터), 산식 구조·변수·Key·주의사항·
  버전 이력 상세, 미리계산기, 유형별 총액 차트, Key 사전으로 구성됩니다. 근거 추적의 변수 역산(`etl.py _calc`)과 화면의
  재계산(`RuleEval`)이 같은 산식 정의를 읽으므로 세 화면의 숫자가 항상 일치합니다. 산식 식별자(RB-*)와 데이터 모델의
  `rule_bank`는 그대로 둡니다.
- **성과 플랫폼 ② 산출 근거 추적**(구 Data Lineage): 성과 등록 12건마다 `etl.py`가 시드 고정으로 생성한
  `lineage`(ERP 스냅샷 ID·동결 시각·레코드 식별자 샘플, Rule 변수 대입값과 재계산 결과, 승인 이력, 연차별 활용평가,
  건전성 점검)를 근거 레인(과제→유형→Key→스냅샷→Rule)과 금액 레인(총액→−역효과→×기여율→−직접비용→순성과→승인→누적)

  역효과 노드와 건전성 패널은 ⑤ 점검의 브라우저 저장 상태를 실시간으로 반영합니다.
- **성과 플랫폼 ⑤ 기여율**: `etl.py CONTRIB_TABLE`(유형별 표준 기여율 테이블 v1, 코드 18종)을 기준으로
  표준(기본값) / 하향(활용부서장 판단) / 상향(재무실 승인) 3구분으로 기여율을 산정합니다. 상향은 승인 전까지 표준값이

  같은 값으로 반영됩니다. C계열은 초안의 단위형/총액형 구분을 반영해 `C-1(2) 판관비 절감(총액형)` 코드를 추가했습니다.
