# PRIDE Demo Dashboard

`docs/PRIDE_Dashboard_Design.md` 설계서의 **Phase 1** 구현체입니다.
CSV 6종(a1~a6) 기반의 정적 데모로, 백엔드 없이 브라우저만으로 동작합니다.

## 실행

```bash
cd demo
python3 -m http.server 8080
# 브라우저에서 http://localhost:8080 접속
```

(`index.html`을 파일로 직접 열어도 동작합니다 — 데이터가 `demo_data.js`로 내장되어 있습니다.)

## My Dashboard — Researcher's Guild 산정 모델

게이미피케이션 레이어는 **새 데이터를 만들지 않고** 기존 `D.me`(a2·a3·a5 파생)와
성과 플랫폼 원장(`D.perf.regs`·`candidates`) 위에서 계산되는 파생 지표다. 규칙은
`index.html`의 `GUILD` 객체 한 곳에만 정의되며, 연구원이 규칙을 알 수 있어야 행동이
바뀌므로 아래에 공개한다.

### 화면 구성 (4행)

| 행 | 구성 | 동작 |
|---|---|---|
| 1 | 프로필·레벨 · Activity Score(등급·전사/연구소 순위·축 칩·성장 힌트) · **내 할 일** | 할 일 클릭 → 해당 건이 선택된 화면(① 워크벤치 / ④ 역효과 / ⑤ 기여율 / ⑥ 승인 / 활동군 상세 / MW 분석) |
| 2 | **내 과제 현황**(내 MW·비중·상태·완료일 D-day·성과 등록 상태) · 성과 실현 요약(기여율 안분, DEMO) | 과제코드 → 활동군 상세, 등록 상태 → ② 산출 근거 추적, 후보 → ① 워크벤치 신규 등록 |
| 3 | Activity Calendar(금년·연환산·최근 3개월·기록 개월) · 역량 프로필(레이더: 나 vs 연구소 상위 25% 선 + 벤치마크) | — |
| 4 | 배지 8종 · 동적 퀘스트 · 성장 여정(실제 날짜만) · 지식자산 | — |

내 할 일은 이번 달 MW 미입력, 내 과제 등록 건의 보완 요청·역효과 미작성·기여율 상향 대기·재무실 검토,
성과 등록 후보 미착수, 90일 내 완료 임박, 금년 지식자산 미등록에서 파생된다.
신규 등록·승인·역효과 상태가 바뀌면 `MY.refreshRegs`로 할 일·과제 표·퀘스트가 즉시 갱신된다.

### Research Activity Score (0~100) — 모델 (a)

4개 축의 **전사 백분위**를 가중 합산하고, 참여자가 극소수인 희소 축은 백분위에서 빼
**활동 범위 보너스**로 가산한다. 희소 축을 백분위에 넣으면 대다수가 0으로 고정돼
점수가 왜곡되고, 1건의 활동이 수십 MW보다 큰 점프를 만들기 때문이다.

| 축 | 원천 | 가중치 |
|---|---|---|
| 전략 프로젝트 | 전략 과제 투입 MW (a2) | 35% |
| 과제 참여 | 참여 과제 건수 (a2) | 25% |
| 지식자산 | 논문·발표·학회 건수 (a5) | 20% |
| 성과 실현 | 참여 완료과제 실현이익의 **내 몫** (DEMO 시뮬레이션, 기여율 안분) | 20% |
| 현업 대응 (보너스) | 현업 과제 참여 시 | +5점 |
| 탐색·혁신 (보너스) | 탐색 과제 참여 시 | +5점 |

백분위의 동률은 **중간 순위(mid-rank)** 로 처리한다 — 값이 없는 다수가 0이 아니라
동률 구간의 중앙에 놓여, 한 건 추가 시 점프 폭이 절반으로 줄고 "0" 낙인이 사라진다.
값이 0인 축은 칩에 백분위 대신 `0건`으로 표시한다.

**기여율 안분**: 성과 실현은 `과제 실현이익 × (내 MW ÷ 과제 전체 MW)`로 계산한다
(`etl.py` `proj_mw_total`). 실운영 시 ⑤ 기여율 확정값으로 대체한다.

**Grade는 전사 상대 분포로 부여하며 어떤 밴드도 20%를 넘지 않는다** —
S+ 상위 2% · S 7% · A+ 15% · A 30% · B+ 45% · B 60% · C+ 80% · C 나머지.

### EXP · Level

| 항목 | 계수 |
|---|---|
| 투입 Man Week | × 10 / MW |
| 참여 과제 | × 300 / 건 |
| 지식자산 | × 500 / 건 |
| 활용중 성과 | × 800 / 건 |
| 부분활용 성과 | × 400 / 건 |
| 내 몫 실현이익 | × 50 / 억 |

레벨 임계값 `EXP(L) = 250 × L^1.6`. 다음 레벨 안내는 남은 EXP를 지식자산·과제·MW 각각으로
환산한 실제 건수를 표시한다.
Tier: Explorer(1+) · Contributor(4+) · Practitioner(7+) · Specialist(10+) ·
Principal Researcher(13+) · Research Master(16+).
Tier는 성장 단계 표시이며 **인사 직급이 아니다** (직급 데이터는 원천에 없다).

### 배지 · 퀘스트 · 성장 여정

- **배지 8종** — 실제 실적으로만 판정하고, 미획득 배지는 남은 조건을 수치로 표시한다.
  활용평가 시뮬레이션에 기반한 Impact Maker·Value Creator에는 DEMO 표기를 붙인다.
- **Growth Quest** — 고정 목록이 아니라 내 상태(MW 미입력, 등록 후보, 역효과 미작성,
  재무실 확정, 완료 임박 등)에서 파생되는 후보 중 미완료 우선 최대 5개. 완료 판정은 실데이터.
- **성장 여정** — 원천에 날짜가 있는 이정표만 표시한다(첫 MW 기록, 지식자산, 성과 등록).
  완료과제는 연도만 있으므로 `YYYY년`으로 표기하고 월을 만들어 붙이지 않는다.

> 활동 이력이 적은 연구원에게는 강점 문구 대신 성장 시작점 문구를 노출한다 —
> 이 화면은 평가 도구가 아니라 성장 기록이기 때문이다.

## 홈 종합현황 — 구성 원칙

홈은 "오늘 무엇이 막혀 있는가"를 30초 안에 파악하는 화면으로, 4행으로 구성됩니다.
모든 수치는 **원천 배지**(a2·a4·a5 / 재무실 확정 / DEMO 시뮬레이션)를 달아 근거를 구분합니다.

| 행 | 구성 | 동작 |
|---|---|---|
| 1 | KPI 6장 — 활동 4종(전략·현업·탐색·지식자산, 전월·전년 추세) + 성과 2종(확정 순재무성과·재무실 승인 대기) | 카드 클릭 → 해당 활동군 상세 / ⑦ 성과 원장 / ⑥ 재무실 승인 |
| 2 | 연구활동 포트폴리오(건수·MW·예산 렌즈 트리맵 + 순위 목록) · 포트폴리오·성과 균형 진단(성과 파이프라인, 역효과 점검 완료율, 기여율 상향 대기, 인당 MW, 지식자산 증감) | 타일·목록 클릭 → 활동군 상세 |
| 3 | Man Week 투입 추이(최근 12개월 vs 전년 동월) · 성과 실현 요약(확정 순재무성과 월별·누적, 장기 활용률·전환율) | ⑦ 성과 원장 / ⑧ 장기 활용평가 링크 |
| 4 | 할 일(승인 SLA·보완·역효과 미작성·기여율 상향·재산출 대기·현업지원 지연·작성 중 초안) · 완료 임박 과제(90일, D-day) · 최근 활동(기준일 이전·중복 제거) | 할 일 클릭 → 해당 건이 선택된 화면으로 이동 |

원천에 없어 산출할 수 없는 항목(현업 MW 비율, 탐색·혁신 MW 비중)은 임의값 대신 **미집계**로 표기합니다.
신규 등록·기여율·역효과·승인 상태가 바뀌면 홈 KPI·진단·할 일이 즉시 갱신됩니다(`HM.refreshRegs`).

## MW 분석 — 구성 원칙

MW 분석은 "투입이 어디에·얼마나·누구에게 몰려 있는가"를 조직 → 과제 → 연구원으로 내려가며 보는 화면이다.

| 행 | 구성 | 동작 |
|---|---|---|
| 1 | KPI 5장 — 실적 누적 MW(계획 제외) · 기준월 투입(전월 대비) · 활동 연구원 · 기준월 미입력 · 인당 연환산 MW(상한 대비 %) | 미입력 카드 클릭 → 연구원 표 미입력 필터 |
| 2 | 월 투입 추이(최근 24개월 활동군 스택 + 전년 동월 선 + 기준월 이후 12개월 계획 점선 막대) · 조직 비교(활동 인원·12개월 MW·인당 MW/상한·전략 비중·전년 대비·미입력) | 조직 행 클릭 → 추이·과제·연구원 표 필터 |
| 3 | 조직 × 월 히트맵(절대값 / 조직별 정규화 토글) · 과제 집중도(투입 상위 과제, 인원, 최다 1인 비중 ≥50% 인원 집중 표시) | 과제코드 클릭 → 활동군 상세 |
| 4 | 연구원별 투입 현황 — 전체 인원, 조직 필터·미입력 필터·검색·헤더 정렬, 재직(기록) 개월·연환산 MW·부하율·기준월 입력 | 행 클릭 → My Dashboard 해당 연구원 |

**계획 분리**: a2에서 기준월(`meta.asOf`의 연-월) 이후의 월 값은 계획으로 분리한다(`etl.py` `ASOF_YM`).
KPI·조직·과제·연구원·My Dashboard의 모든 누적값은 실적만 합산하고, 계획은 월 추이 차트에서만
점선 막대로 표시한다. (분리 전에는 2026년 9~12월·2027년 계획 6,514 MW가 실적 누적에 섞여 있었다.)

**부하율 통일**: 인당 적정 투입 상한은 `CAP_MW_YEAR = 44 MW/년`(월 3.67 MW) 하나로 정의하고
홈 균형 진단·MW 분석·투입 시뮬레이터가 같은 값을 쓴다(시뮬레이터의 4.3 MW/월 상수 제거).
연구원 부하율 = 연환산 MW(실적 누적 ÷ 첫 기록~마지막 기록 개월 × 12) ÷ 44 —
과부하 ≥120% · 저부하 <40% · 최근 12개월 기록이 없으면 "기록 종료"로 판정에서 제외한다.

## 활동군 상세 › 전략 프로젝트 — 구성 원칙

진행중 전략 과제 전체(a3, W·N 코드 제외)를 `D.detail.strategy.projects`로 내려보내고 KPI·차트·필터를
클라이언트에서 집계한다. 설계서 4.1의 "KPI → 메인 차트 → 목록(드릴다운 종착지)" 레이아웃을 따른다.

| 행 | 구성 | 동작 |
|---|---|---|
| 0 | **초대형 과제 제외 토글** — 연구비 500억 이상(`megaEok`) 과제를 KPI·차트·표에서 제외 | 한 과제가 총액을 지배하는 왜곡 제거 |
| 1 | KPI 6장 — 진행 과제(금년 착수) · 진행 연구비 · **집행률(집행예산 등록 과제 기준, 기간 경과율 병기)** · 기대이익(정량효과 과제) · 실적 투입 MW(계획 제외) · 완료 임박(90일)/기한 경과 | 카드 클릭 → 표 필터 |
| 2 | 포트폴리오 버블(X 연구비, Y 기대이익, 로그축, 크기 실적 MW, 색 연구소, 기대이익 미산정은 하단 띠) · 진행 현황(다단계 과제 현단계 분포, 완료 예정 시점 히스토그램) | 버블 클릭 → 과제 카드 |
| 3 | 기술분류 × 연구소 스택 막대(상위 12 + 기타) · 과제 구성(과제유형·연구성격·성과유형 100% 스택) | 조각 클릭 → 표 필터 |
| 4 | 진행중 전체 표 — 연구소·과제유형·연구성격·성과유형·상태(임박/경과/금년 착수/다단계) 필터, 검색, 헤더 정렬, 기대이익·실적 MW·D-day·단계 열 | 코드 → **과제 카드**, 책임자 → My Dashboard, 연구부서 → MW 분석(연구소 필터) |

**과제 카드**: 개요(부서·책임자·유형·성격·활용부서·기술분류), 연구비·집행·기대이익·실적 MW·기간 경과·단계,
성과 등록 상태(원장 등록 건은 ② 산출 근거 추적 링크, 후보, 완료 후 등록 대상), 참여 인력 상위 8명(실적 MW,
이름 클릭 → My Dashboard), 최근 12개월 월별 실적 MW(`etl.py` `proj_ym`).

**집행률 재정의**: 집행예산이 등록된 과제만 대상으로 `Σ집행예산 ÷ Σ연구비`를 계산하고, 같은 과제들의
평균 기간 경과율을 병기한다(집행률 < 경과율이면 "지연"). 미등록 과제를 0으로 넣어 집행률을 끌어내리던
이전 산식을 대체한다. 연구소 단위 집계·필터는 `top_org`(연구소/연구원, 그 외 기타)를 쓴다.

## 투입 시뮬레이터 — 구성 원칙

설계서 5.1 ④ "이 과제를 받으면 누가 과부하가 되는가"에 답하는 팀장 도구다.

| 행 | 구성 | 동작 |
|---|---|---|
| 1 | 입력 — 조직 · 과제 유형(전략/현업/탐색) · 필요 MW/월 · 시작월(기준월+1 ~ +18) · 기간 · 시나리오 이름/저장 | 입력 즉시 재계산 |
| 2 | KPI 5장 — 활동 인원 · 가용 MW/월 · 현재 투입(6개월 평균) · 기간 중 최대 부하율 · 판정(시작 가능 / 가장 이른 시작월) | 활동 인원 카드 클릭 → MW 분석 조직 필터 |
| 3 | 월별 조직 부하율(실적 6개월 + 계획 18개월 + 신규 과제 스택, 부하율 선, 상한 90% 선, 피크 표시) + 판정 문구 · 시나리오 비교(최대 3개, 브라우저 보관) | 불러오기로 입력·배정 복원 |
| 4 | 배정 시뮬레이션 — 활동 인원만, 유형 일치 → 여력 → 최근 실적 순, 배정 MW 입력 시 개인 부하(기간 평균)·합계·과부하 인원 즉시 계산 | 이름 클릭 → My Dashboard |

**모델**
- 가용 = 활동 인원(최근 12개월 기록) × 3.67 MW/월. 기록 종료 인원은 가용·후보에서 제외한다.
- 미래 투입 = a2 계획 월 값(등록된 과제 기준). 계획이 없는 월은 마지막 계획값을 유지한다.
  부하율(월) = (계획 + 신규) ÷ 가용, 판정은 과제 기간 전체가 상한 90% 이내인지로 하며,
  초과 시 18개월 안에서 가장 이른 시작 가능월을 찾는다.
- 개인 여력 = 3.67 − 과제 기간 중 개인 계획 투입 평균. 배정 후 부하 > 100% 과부하, 90~100% 상한 초과.
- 시나리오는 `localStorage` `pride.sim.v1`에 입력·배정을 함께 저장한다(시연용, 실운영 시 서버 보관).
